## 1. 设计目标

v0.6.5 的目标不是重写现有语音助手，而是在 v0.6.4 已验证能力上进行受控增量增强，使手机用户获得更自然、更快、更可信的使用体验，同时建立明确的冻结保护和发布闸门，防止后续新增能力破坏已经正常的功能。

本版本解决六类已确认问题：

1. “退出微信”等指令不能执行，当前会落到“不支持指令”。
2. 用户说完指令后，小智理解和响应体感偏慢。
3. 所有真正操作手机的执行型指令，在执行前都应先播报“某指令正在执行”。
4. 界面只有在麦克风真实开始采集后，才能显示“正在听你说…”。
5. 提高命令录音阶段对环境噪声的适应能力，减少漏听、没听清、短指令开头丢失和背景噪声误触发。
6. 每次执行型指令成功或失败，都要更新手机通知栏中的小智常驻通知，显示最近一次执行结果。

总体验原则：

- **快：** 本地可确定的设备操作优先本地处理，不无谓等待 AI。
- **准：** “听不清”“听清但不理解”“理解后执行失败”必须区分。
- **真：** UI 状态必须反映真实底层状态，不提前显示监听或成功。
- **稳：** 已验证正常能力必须冻结；新增能力通过外围模块扩展。
- **安全：** AI 负责理解时仍不拥有任意 Android 执行权限，所有工具调用继续经过安全白名单。
- **自然：** 用户始终能感知“小智听到了、正在做、做完了或失败了”，但提示不能拖慢操作。

## 2. 已确认产品决策

### 2.1 “退出微信”的语义

“退出微信 / 关闭微信 / 离开微信”采用 **返回手机桌面、让微信退到后台** 的语义，不强制终止微信进程，不使用 root，不申请系统级强杀权限。

同一语义扩展至：

- 退出 QQ
- 退出高德地图
- 退出百度地图
- 退出抖音
- 退出淘宝
- 退出浏览器
- 其他“退出/关闭/离开 + App 名称”表达

如果用户仅说“退出 / 退下 / 没什么事了 / 再见”等，则仍代表结束当前与小智的会话。

因此语义优先级固定为：

1. `退出/关闭/离开 + 明确 App 名称` → 返回桌面，保持小智会话。
2. `单独退出语义` → 退出小智会话。

### 2.2 命令识别模式

采用“平衡模式”：

- 目标尾部静音窗口约 **600–700ms**，默认设计值约 **650ms**。
- 继续使用 16kHz 单声道本地录音和现有 Paraformer。
- 命令录音阶段增加自适应环境噪声基线、动态 VAD 阈值、预录缓冲和可用时的 Android `NoiseSuppressor`。
- 不通过修改 KWS 阈值来解决命令识别问题。

### 2.3 通知栏策略

只更新现有前台服务常驻通知 `NOTIFY_ID`，不为每条命令创建新的独立通知。

执行状态示例：

- `⏳ 正在执行：打开微信`
- `✅ 已成功执行：打开微信`
- `❌ 执行失败：打开微信`

最近一次执行结果需要短暂保留，不能刚执行完成就立即被“正在监听”覆盖。实时监听状态由悬浮层承担。

### 2.4 执行前语音提示范围

只有真正会操作手机的**执行型指令**播报“某指令正在执行”。普通 AI 对话不播报该提示。

示例：

- “打开微信” → “打开微信正在执行”
- “退出微信” → “退出微信正在执行”
- “把媒体音量调到 70%” → “调整媒体音量到百分之七十正在执行”
- “导航到泉水村” → “导航到泉水村正在执行”

“你是谁”“解释一下 AI”等普通问答直接进入思考/回答。

### 2.5 执行时机

执行型指令的 TTS 开始播报后约 **100–150ms** 即开始真正执行，默认目标约 **120ms**。

允许并行的是：

- TTS 执行前提示
- Android 设备操作

禁止并行的是：

- TTS
- 命令 ASR 麦克风监听

这样既有“正在执行”的即时反馈，又不会人为等待整句 TTS 说完才开始操作。

## 3. 架构策略：方案 2，小范围模块化

不重写完整语音管线，也不继续把所有逻辑堆进 `WakeService.kt`。

v0.6.5 采用外围模块扩展：

### 3.1 `AdaptiveVoiceActivityDetector`

职责：

- 估算环境底噪。
- 计算动态人声开始阈值。
- 计算动态人声结束阈值。
- 判断稳定人声开始。
- 判断连续静音结束。
- 保证短暂自然停顿不立即截断。

依赖输入为每帧 RMS 或等价轻量特征，不引入新的云端服务。

### 3.2 `AudioEnhancementManager`

职责：

- 在设备支持时为当前 `AudioRecord` 会话启用 Android `NoiseSuppressor`。
- 设备不支持时安全降级，不影响录音启动。
- 释放与录音会话绑定的音效对象。

该模块只增强**命令录音阶段**，不修改 KWS 模型及 KWS 初始化参数。

### 3.3 `ExecutionFeedbackCoordinator`

职责：

- 统一执行型指令生命周期。
- 先生成并开始播放执行前提示。
- 约 100–150ms 后触发真正 Android 操作。
- 获取真实执行结果。
- 更新成功/失败通知。
- 播放最终结果 TTS。
- TTS 完全结束后重新进入真实监听。

该模块避免本地指令与 AI Tool 指令分别复制一套“提示/执行/结果/重听”逻辑。

### 3.4 `CommandResultNotifier`

职责：

- 复用当前前台服务通知渠道和 `NOTIFY_ID`。
- 格式化 `RUNNING / SUCCESS / FAILURE` 三类执行结果。
- 保留最近一次结果一段短时间。
- 不额外堆积通知。

### 3.5 `AppExitController`

职责：

- 处理返回桌面动作。
- 使用 Android Home Intent。
- 返回结构化成功/失败结果。
- 不声称已强杀 App。
- 不使用 root、Accessibility、shell 或隐藏系统 API。

### 3.6 `ExecutionIntentFormatter`

职责：

- 将内部动作转换成简洁自然中文执行提示。
- 将结果转换成最终播报和通知摘要。
- 保证同一动作的提示、通知、最终回复一致。

## 4. 命令处理优先级

v0.6.5 的命令处理顺序固定为：

1. 离线 ASR 输出。
2. `VoiceCommandNormalizer` 文本规范化。
3. 明确退出小智会话检测。
4. 明确本地设备命令解析。
5. 本地同义表达、App 名称、参数解析。
6. 如果本地能可靠确定动作，直接进入安全执行链。
7. 只有本地确实不能确定时，才进入 AI 语义判断或 AI 普通对话。
8. AI Tool 结果仍必须经过 `SafeToolExecutor` 白名单。

目标：手机控制类命令尽量不把网络 AI 作为必经步骤。

### 4.1 新增本地语义

至少支持：

- `退出/关闭/离开 + App 名称` → `GO_HOME`
- `返回桌面 / 回到桌面 / 回桌面` → `GO_HOME`
- “把微信退了 / 退一下微信 / 微信先关掉”等自然表达 → `GO_HOME`

### 4.2 不能把失败统一解释成“不支持”

错误类型至少区分：

- `NO_SPEECH`：没有检测到用户讲话。
- `ASR_EMPTY`：检测到讲话但 ASR 没有有效文本。
- `UNSUPPORTED_COMMAND`：听清了但当前确实不支持。
- `APP_NOT_FOUND`：没有找到目标 App。
- `EXECUTION_FAILED`：理解正确但 Android 操作失败。
- `AI_UNAVAILABLE`：AI 服务失败。
- `SAFETY_REJECTED`：安全工具层拒绝执行。

对用户的语言必须与真实原因一致。

## 5. 智能监听设计

## 5.1 UI 状态必须与真实硬件同步

“正在听你说…”的进入条件不是“准备开始监听”，而是：

1. `AudioRecord` 已创建。
2. `AudioRecord.state == STATE_INITIALIZED`。
3. `startRecording()` 已成功调用。
4. 录音线程进入有效采集阶段。
5. 此时才进入 `ConversationState.LISTENING` 并显示“正在听你说…”。

如果录音初始化或启动失败，不得显示 LISTENING。

停止采集后必须立即离开 LISTENING，进入 `RECOGNIZING`。

### 5.2 状态文案规范

- `LISTENING` → “正在听你说…”
- `RECOGNIZING` → “正在识别…”
- 需要本地/AI语义判断时 → “正在理解…”
- `EXECUTING` → “正在执行…”
- `SPEAKING` → “正在回复…”
- `READY_TO_LISTEN` → “准备继续监听…”
- `EXITING` → “正在退出…”

禁止 TTS 正在说话时显示 LISTENING。

## 5.3 自适应 VAD

现有固定 RMS 判定升级为动态底噪模型。

建议行为：

- 在尚未检测到稳定人声时，对低能量帧进行平滑环境噪声估计。
- 动态开始阈值 = 环境基线 + 最小安全余量，并设置上下限，避免极安静时过敏或极嘈杂时完全失效。
- 动态结束阈值低于开始阈值，形成滞回区间，避免边界抖动。
- 连续多帧超过开始阈值才判定“开始说话”。
- 稳定人声开始后停止快速跟随高能量声音更新噪声基线，避免把用户自己讲话当成环境噪声。
- 结束条件主要基于约 650ms 连续低于动态结束阈值，同时保留最短有效语音长度约束。

具体常数在实施阶段通过源码测试和真机反馈微调，但不得触碰冻结 KWS 参数。

## 5.4 Pre-roll

保留预录缓存，并允许从当前约 300ms 适当增加，以减少“打开微信”被截成“开微信/微信”的概率。

预录缓存只在检测到稳定人声开始后拼接入本次命令音频，不长期保存，也不上传网络。

## 5.5 NoiseSuppressor

如果 `NoiseSuppressor.isAvailable()` 且当前录音 session 支持：

- 创建并启用。
- 绑定到当前命令录音 session。
- 录音结束时释放。

如果不可用或创建失败：

- 记录安全诊断。
- 自动回退到自适应 VAD + 原始录音。
- 不得导致本地语音功能不可用。

## 5.6 没听清的智能恢复

行为：

- 完全未检测到讲话：不立即播错误，自动继续监听。
- 检测到讲话但 ASR 空结果：提示“刚才没有听清，请再说一次。”并重听。
- 明显异常、极短或无法映射的识别结果：允许一次快速恢复，不立即声称“不支持”。
- 连续失败达到既定上限后，再给清晰的用户提示。

“没听清”和“不会这个功能”必须彻底分离。

## 6. 执行型指令事务

统一定义 `CommandTransaction` 概念，至少包含：

- 原始 ASR 文本。
- 规范化文本。
- 动作类型。
- 动作目标与参数。
- 执行前播报文本。
- 开始执行时间。
- 真实执行结果。
- 成功/失败状态。
- 用户可理解结果文本。
- 通知摘要。
- 最终 TTS 文本。

### 6.1 标准事务时序

示例“打开微信”：

1. 识别为 `OPEN_APP("微信")`。
2. 麦克风保持关闭。
3. 悬浮层进入 EXECUTING。
4. 小智开始说“打开微信正在执行”。
5. 约 120ms 后触发 `AppLauncher`。
6. `AppLauncher` 返回真实结果。
7. 通知栏更新：`✅ 已成功执行：打开微信` 或 `❌ 执行失败：打开微信`。
8. 播放最终结果：“微信已打开，请继续说。”或对应失败原因。
9. 等最终 TTS `onDone`。
10. 创建并启动下一轮 `AudioRecord`。
11. 真正开始采集后才显示“正在听你说…”。

### 6.2 结果必须使用真实值

音量指令执行后重新读取 `STREAM_MUSIC` 当前值，用真实百分比播报。例如用户请求 70%，系统实际映射为 69%，最终播报和通知使用 69%。

打开 App、地图、手电等也必须以现有控制器返回值决定成功或失败，不能预先假定成功。

## 7. 通知栏交互

### 7.1 继续复用前台服务通知

保持当前前台服务通知，不新增一组独立指令通知。

`CommandResultNotifier` 通过现有 `NOTIFY_ID` 更新内容。

### 7.2 执行结果优先保留

执行期间：

`⏳ 正在执行：<动作>`

成功：

`✅ 已成功执行：<动作结果>`

失败：

`❌ 执行失败：<动作>`

执行完成后，即使悬浮层已经进入下一轮 LISTENING，通知栏结果也至少短暂保留，避免立即被“连续会话中”覆盖。

退出当前会话并恢复 KWS 待机后，通知最终恢复为：

`全离线语音已开启 · 说“<当前自定义唤醒词>”`

## 8. AI 智能化边界

### 8.1 AI 不是设备执行总线

AI 可以：

- 处理普通问答。
- 对本地低确定度语句做语义分类。
- 生成安全工具调用候选。

AI 不可以：

- 绕过 `SafeToolExecutor`。
- 任意执行 Android Intent、shell、支付、删除、转账、安装卸载等动作。
- 因语义不确定而自行扩大权限。

### 8.2 本地优先

下列高确定度命令不应依赖网络 AI：

- 打开/退出已安装 App。
- 返回桌面。
- 音量。
- 手电筒。
- 播放/暂停/上一首/下一首。
- 地图打开、导航、附近搜索等现有明确模式。

### 8.3 低确定度不乱执行

如果本地解析明显不可靠：

- 可以进入 AI 意图分类。
- 分类结果仍必须映射到允许的内部动作。
- 无法可靠判断时不执行，提示用户重新说。

## 10. 允许修改的边界

- 命令录音阶段 VAD。
- 命令录音的 `NoiseSuppressor` 增强。
- `CommandRouter` 的通用“退出 App / 回桌面”解析。
- `PhoneController` 或独立控制器的 Home Intent 能力。
- 执行型指令反馈协调器。
- 通知栏结果协调器。
- `WakeService` 的命令会话编排部分。
- 对话状态增加必要的新细分状态或内部阶段，只要现有 UI 语义兼容。
- 新测试、发布闸门和源码验证。

不得修改一级冻结对象。

如果实施中发现确实必须修改一级冻结对象，必须停止开发，明确说明原因并取得用户新的显式授权，不能自行修改。

- 动作触发目标窗口为 TTS 开始后约 100–150ms。
- TTS 与设备操作可并行。
- TTS 与命令监听不得并行。
- 成功生成 `✅` 通知结果。
- 失败生成 `❌` 通知结果。
- 最终成功/失败播报基于真实执行返回值。

### 11.4 监听状态

- `AudioRecord` 未初始化成功时不得进入 LISTENING。
- `startRecording()` 前不得显示“正在听你说…”。
- 停止录音后立即进入 RECOGNIZING。
- TTS 时不得进入 LISTENING。
- TTS `onDone` 后才能重新启动下一轮麦克风。

### 11.5 抗噪与 VAD

- 动态噪声基线会随安静背景平滑调整。
- 人声高能量帧不会立即污染噪声基线。
- 短促单帧噪声不能轻易触发稳定讲话。
- 连续稳定人声可以触发讲话开始。
- 约 650ms 连续静音结束本次命令。
- pre-roll 被保留并拼入识别音频。
- `NoiseSuppressor` 不可用或创建失败时安全降级。

### 11.6 错误恢复

- 没有检测到讲话 → 自动继续监听，不说“不支持”。
- ASR 空结果 → “刚才没有听清，请再说一次。”
- App 不存在 → 明确“没有找到应用”。
- 执行失败 → 明确“没有成功执行”。
- AI 失败 → 明确 AI 服务暂时不可用。

### 11.7 安全回归

- SafeToolExecutor 白名单不扩大到危险操作。
- 不增加 shell、root、强杀 App、支付、删除、自动发送消息等能力。
- 源码不得包含用户 API Key 或 secret-like token。

## 13. 实机验收顺序

构建成功后按以下顺序验收：

1. 首先验证一级冻结功能：“小白小白”自定义唤醒仍正常。
2. 唤醒后确认 TTS 结束，真实麦克风启动后才显示“正在听你说…”。
3. “打开微信” → 执行前提示 → 快速打开 → 成功通知 → 最终播报 → 自动继续监听。
4. “退出微信” → 执行前提示 → 返回桌面 → 成功通知 → 不退出小智会话。
5. 单独“退出” → 正常退出小智会话并恢复 KWS。
6. 音量 70% / 最大 / 一半 / 静音 / 大一点 / 小一点。
7. 高德/百度地图、导航、附近搜索。
8. 噪声环境下的短指令、带短暂停顿的指令和正常连续对话。
9. 制造一个不存在 App 的失败场景，确认失败通知与播报准确。
10. AI 普通问答与安全 Tool 调用。

## 14. 非目标

v0.6.5 不做以下事项：

- 不重写 KWS。
- 不替换自定义唤醒模型。
- 不更换 Paraformer 基础模型。
- 不使用 root。
- 不加入 Accessibility 自动操作框架。
- 不强制停止其他 App 进程。
- 不实现支付、转账、删除等高风险控制。
- 不引入新的云端语音识别服务。
- 不对 UI 做与本次体验问题无关的大规模重构。

## 15. 完成标准

只有同时满足以下条件，v0.6.5 才能进入“可交付 APK”状态：

- 一级冻结全部通过。
- 二级冻结行为回归全部通过。
- 新增智能监听、抗噪、退出 App、执行反馈、通知结果测试全部通过。
- 安全回归通过。
- GitHub Actions 真正完成 Android 编译。
- Artifact 中 APK 完整有效。
- APK 保留 arm64-v8a、sherpa JNI、KWS 模型、Paraformer 模型和完整 Manifest/classes.dex。
- 实机首先通过自定义“小白小白”唤醒验收。
- 用户反馈的六类问题均有对应真机验收结果。

## 16. 后续演进原则

从 v0.6.5 开始，版本演进遵循：

> 新增功能默认不得修改已经冻结的底层能力；如必须修改二级冻结模块，先增加或强化对应回归测试，再修改实现。一级冻结 KWS 链未经用户明确授权不得修改。

目标是让稳定能力逐层积累：

`v0.6.4 稳定基线 → 冻结 → v0.6.5 新智能体验 → 冻结 → 后续能力继续增量扩展`。
